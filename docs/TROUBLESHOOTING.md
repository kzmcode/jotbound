# トラブルシューティング

**まず `npm run doctor` を実行してください。** 設定ファイルの不足や、プロジェクトの食い違いなど、よくある原因を一覧で表示します。

アプリに表示される文言ごとに、主な原因と対処をまとめます。AI 解析に失敗しても録音は端末に残っているので、手入力で続けることもできます。

## AI 解析

まず **設定 → AI 解析 → AI 接続を確認** を押して、AI につながるかを確かめてください（短いリクエストを1回送ります）。

| 表示 | 主な原因 | 対処 |
| --- | --- | --- |
| 本日の無料利用枠、または短時間あたりの上限に達した可能性（429） | Gemini Developer API の無料枠、または AI Logic のユーザーごとのレート制限 | 時間をおいて「再試行」を押します。アプリは自動では再試行しません。上限は変わることがあるので、[Gemini API のレート制限](https://ai.google.dev/gemini-api/docs/rate-limits) を確認してください |
| AI の利用が許可されませんでした（403） | App Check のトークンがない・無効 | 下の「App Check」を確認します |
| ログイン情報を確認できませんでした（401） | 認証済みユーザー限定モードで、ログイン情報が古い | ログアウトしてから、もう一度ログインします |
| Firebase AI Logic が設定されていない可能性（404） | AI Logic を有効にしていない、または反映待ち | [SETUP_JA.md](SETUP_JA.md) の手順 7 を行います。有効にしてから数分かかることがあります |
| 録音データが大きすぎる（413） | 送信の上限（20MB）を超えた | もっと短く録音し直します。アプリの録音上限は 2 分・10MB です |
| 通信できませんでした | オフライン、またはタイムアウト（90 秒） | 通信状況を確認して再試行します |
| AI の応答の形式が正しくありませんでした | AI の応答が想定した JSON でなかった | 再試行するか、手入力で続けます。何度も起きる場合は、録音を短くして1件の話題に絞ります |
| AI から応答を得られませんでした | 安全性のフィルターなどで応答が止まった | 手入力で続けます |

### 抽出結果がおかしいとき

- **書名が違う・候補が複数出る:** 本の詳細画面で「別名」に略称や読みを登録すると、照合しやすくなります。
- **引用が原文と違う:** 引用は話した内容をそのまま書き起こしたもので、原文と一致することは保証されません。保存の前に確認・修正してください。
- **複数のメモが含まれていると表示される:** 1回の録音は1件のメモになります。別の話題は録音を分けてください。

## App Check

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 開発中（`npm run dev`）に AI だけ 403 になる | デバッグトークンが未登録 | ブラウザのコンソールに出る `App Check debug token: …` を、Firebase コンソール → App Check → アプリ → **デバッグトークンを管理** に登録します |
| コンソールに `exchangeDebugToken … 403` が出る | 同上 | 同上。登録後にページを再読み込みします |
| ブラウザやシークレットウィンドウを変えたら 403 になった | デバッグトークンはブラウザごとに変わる | 新しく出たトークンも登録します |
| 公開したアプリで 403 になる | reCAPTCHA キーに公開ドメインが登録されていない、またはサイトキーが違う | Google Cloud コンソールの reCAPTCHA で、キーのドメインに `<project-id>.web.app` と `<project-id>.firebaseapp.com` が入っているかを確認します。`.env.local` の `VITE_RECAPTCHA_ENTERPRISE_SITE_KEY` を直したら、ビルドし直してデプロイします |
| `Unrecognized feature: 'private-token'` という警告が出る | reCAPTCHA のスクリプトが出す警告 | 動作に影響はないので、無視して構いません |

- **reCAPTCHA キーに `localhost` を追加しないでください:** 追加すると、誰でも自分の端末からアプリを動かして App Check を通れてしまいます。開発中はデバッグトークンを使います。
- **使用量を確認する:** Firebase コンソール → **App Check** で、確認済み・未確認のリクエストの割合を見られます。

## 録音

| 表示 | 対処 |
| --- | --- |
| マイクへのアクセスが許可されていません | **iPhone:** 設定 → Safari（またはホーム画面のアプリ）→ マイク を「許可」にします。**パソコン:** アドレスバーの鍵アイコン（サイト設定）から、マイクを「許可」にします |
| この端末・ブラウザでは録音できません | 対応する録音形式がありません。最新の Safari・Chrome・Edge で開くか、手入力でメモを残します |
| 録音を端末に保存できませんでした（エラー名） | 端末の空き容量を確認します。iPhone の「設定 → Safari → 詳細 → Web サイトデータ」やコンテンツブロッカーでサイトデータが制限されていないかも確認してください。解決しない場合は、括弧内のエラー名を添えて報告してください |
| 録音が途中で止まった | 画面のロックやアプリの切り替えで止まることがあります。下書きが残っていれば、ホームの「確認待ち」から開けます（残らないこともあるので、録音中は画面を開いたままにしてください） |
| 確認待ちの録音が消えた | ブラウザのサイトデータを消すと、下書きも消えます。保存したメモは Firestore に残っています |

- **録音は https でだけ動きます:** マイクは https（または `localhost`）でしか使えません。公開したアプリは `https://<project-id>.web.app` で開いてください。

## ログイン

| 症状 | 対処 |
| --- | --- |
| 「このアカウントでは利用できません」と表示される | Security Rules の所有者 UID と違うアカウントでログインしています。正しいアカウントでログインするか、[SETUP_JA.md](SETUP_JA.md) の手順 9 で所有者を設定し直します（`npm run owner:set -- <UID>` → `npm run deploy:rules`） |
| ホーム画面に追加した PWA や iPhone でログインできない・ログイン画面から戻ってこない | [SETUP_JA.md](SETUP_JA.md) の手順 5（リダイレクト URI の追加）を確認します。`npm run doctor` で `VITE_FIREBASE_AUTH_DOMAIN` が `<プロジェクトID>.web.app` になっているかも確認し、直したら `npm run deploy` で公開し直します |
| 公開したアプリで `auth/unauthorized-domain` が出る | Firebase コンソール → Authentication → Settings → **承認済みドメイン** に公開ドメインを追加します |

## 書籍の検索

| 症状 | 対処 |
| --- | --- |
| ISBN で見つからない | Google Books API の不具合で、2026-10 から ISBN 指定の検索が 0 件になることがあります。「書名で検索」か、ISBN を引き継いだ手入力で登録します |
| 検索が使えない・上限に達した | `VITE_GOOGLE_BOOKS_API_KEY` を設定します（[SETUP_JA.md](SETUP_JA.md) の手順 10）。キーのリファラー制限に、公開ドメインが入っているかも確認します |
| 書影が出ない | 提供元に画像がないと、書名入りの代わりの表紙を表示します。動作には影響ありません |

## バックアップの読み込み

| 表示 | 対処 |
| --- | --- |
| このアプリのバックアップ形式ではありません | 設定 → **JSON で書き出す** で作ったファイルを選びます。Markdown は読み込めません |
| 取り込めない項目が N 件あります | プレビューの一覧に理由が出ます。ほかの項目は取り込めます |
| 途中で失敗しました | 通信状況を確認して、同じファイルをもう一度読み込みます。同じ ID で書き込むので重複しません |
| 読み込みがオフラインで押せない | 読み込みはオンラインのときだけ行えます |

## 導入・公開

| 症状 | 対処 |
| --- | --- |
| `npm run setup` が「ログインしていません」で止まる | `npx firebase login` を実行してから、もう一度 `npm run setup` を実行します |
| `npm run setup` で別のアカウントが表示される | `npx firebase login:add` で追加し、`npx firebase login:use <メールアドレス>` で切り替えます |
| プロジェクトを作れない | プロジェクト ID が他の人と重複しています。別の ID にします。作成できるプロジェクト数の上限に達している場合は、使っていないプロジェクトを削除します |
| `npm run deploy` が点検（doctor）で止まる | 表示された ✗ の項目を直します。多くは `npm run setup` をもう一度実行すれば直ります |
| `npm run deploy` が秘密情報のチェックで止まる | 表示されたファイルから秘密情報を取り除きます。`firestore.rules` に UID が書かれている場合は、`npm run owner:set -- <UID>` で `.env.local` に移し、`firestore.rules` を `return []; // OWNER_UIDS` に戻します |
| `npx firebase deploy` で Rules のファイルが見つからない | Security Rules はデプロイのたびに生成します。`npm run deploy` か `npm run deploy:rules` を使ってください |
| 公開したのに古い画面のまま | アプリに「新しいバージョンがあります」と出たら **更新する** を押します。出ない場合は、アプリを閉じて開き直します |

## 無料枠と使用量の確認

| 確認したいこと | 場所 |
| --- | --- |
| プラン（Spark のままか） | Firebase コンソール → 左下のプラン表示 |
| Firestore の読み書き回数 | Firebase コンソール → Firestore → **使用状況** |
| Hosting の転送量・保存容量 | Firebase コンソール → Hosting → **使用状況** |
| AI Logic のリクエスト数 | Firebase コンソール → AI Logic → **使用状況とモニタリング** |
| App Check の判定 | Firebase コンソール → App Check → **API** タブの各サービス |
| reCAPTCHA の評価回数 | Google Cloud コンソール → セキュリティ → reCAPTCHA |

コンソールの画面の表記は変わることがあります。


- **無料枠の上限について:** 上限の値は変わることがあるので、[Firebase の料金](https://firebase.google.com/pricing) と各サービスのドキュメントで確認してください。
### Firestore の読み取り回数の目安

Jotbound は検索をすべて端末内で行うため、アプリを開くと本・メモ・タグを購読します。

- **前回から30分以上たってアプリを開いた場合:** 全件が読み取りとして数えられます（[公式](https://firebase.google.com/docs/firestore/pricing)）。30分以内に開き直した場合は、変わった分だけが数えられます。
- **Spark の無料枠:** 読み取りは1日5万回です（太平洋時間の午前0時ごろにリセット）。

| 本・メモ・タグの合計 | 1回開いたときの読み取り | 1日に開ける回数の目安 |
| --- | --- | --- |
| 1,000件 | 約1,000回 | 約50回 |
| 5,000件 | 約5,000回 | 約10回 |
| 10,000件 | 約10,000回 | 約5回 |

上限に達すると、その日は新しいデータを読み込めなくなります（端末にキャッシュ済みの分は表示できます）。料金は発生しません。

- **Spark プランなら課金されません:** Spark プランのまま（Cloud Billing を紐付けない）なら、上限に達するとその日は使えなくなるだけで、料金は発生しません。
